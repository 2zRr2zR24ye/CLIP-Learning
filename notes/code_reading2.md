## simple_tokenizer.py:
这段代码实现了一个 **简单的 BPE（Byte Pair Encoding）分词器**，它的设计目标与 OpenAI 的 **CLIP** 模型所使用的 tokenizer 基本一致。

简单来说，它的作用是：

1. **将原始文本（例如一句英语）转换成一系列整数 ID**（编码），这些 ID 可以被神经网络（如 CLIP 的文本编码器）直接使用。
2. **反过来，也能将整数 ID 列表还原回文本**（解码），方便查看或调试。

为了实现这一点，它做了以下几件事：

- 加载一个预训练好的 **BPE 合并规则文件**（`bpe_simple_vocab_16e6.txt.gz`），这个文件里记录了字节对合并的优先级。
- 定义了一套 **字节到 Unicode 字符的映射**，使得 BPE 算法可以在 Unicode 字符串上安全运行，同时避免处理控制字符或空格等“麻烦”字符。
- 提供了 `encode()` 和 `decode()` 方法，分别完成文本<--->token IDs 的转换。
- 内部还包含：
  - 文本的 **基本清洗**（如修复 unicode 编码问题、解 HTML 实体、去掉多余空白）。
  - 一个 **正则表达式** 来切分单词和标点（比如 `'s`, `'t`, `<|startoftext|>` 等特殊 token 也会被识别）。
  - 用 `@lru_cache` 缓存默认 BPE 文件的路径，以及内部的 `bpe()` 结果，提高重复 token 的处理速度。

**简单说，这是一个专门为英文设计的、与 CLIP 兼容的轻量级分词器，基于 BPE 算法，支持 start/end 特殊标记。**

  构建基础字符列表 bs

  bs = list(range(ord("!"), ord("~")+1)) + list(range(ord("¡"), ord("¬")+1)) + list(range(ord("®"), ord("ÿ")+1))

  分三段收集可见的、非控制字符的 Unicode 码点：

  ┌─────────────────────┬─────────┬───────────────────────────┐
  │         段          │  范围   │           字符            │
  ├─────────────────────┼─────────┼───────────────────────────┤
  │ ord("!") ~ ord("~") │ 33~126  │ 基本拉丁可打印字符 ! 到 ~ │
  ├─────────────────────┼─────────┼───────────────────────────┤
  │ ord("¡") ~ ord("¬") │ 161~172 │ 拉丁扩展符号              │
  ├─────────────────────┼─────────┼───────────────────────────┤
  │ ord("®") ~ ord("ÿ") │ 174~255 │ 更多拉丁扩展              │
  └─────────────────────┴─────────┴───────────────────────────┘

  故意跳过了控制字符（0~32, 127~160）和 （173，软连字符）——这些 BPE 算法处理起来会有问题。

  为不在 bs 中的字节创建映射

  cs = bs[:]        # cs 初始和 bs 一样
  n = 0
  for b in range(2**8):   # 遍历 0~255 的所有字节
      if b not in bs:      # 如果这个字节不在可见字符列表中
          bs.append(b)     # 把原始字节值加入 bs
          cs.append(2**8+n) # 给它分配一个 256+ 的 Unicode 码点
          n += 1

  - 256 个可能字节中，bs 已有 ~188 个可见字符，还剩 ~68 个控制/不可见字符。
  - 这些不可见字节被映射到 256, 257, 258, ... 的 Unicode 码点（属于拉丁扩展-B 等区块）。
  - 目的：每个原始字节都有一个唯一的 Unicode 字符表示，且这些 Unicode 字符不会与 BPE 的特殊控制符冲突。
  构建最终字典

  cs = [chr(n) for n in cs]   # 码点 → 字符
  return dict(zip(bs, cs))     # {字节值: Unicode字符}


  我的理解是：  
  - 本来就看得见的（比如 A=65，!=33）：保留不动，继续映射到 A、!
  - 看不见的（比如换行=10）：映射到一个特殊的可见字符，比如 Ā（拉丁大写 A 带横线）

  结果类似：
  10 (换行符) → 'Ā'   ← 本来是看不见的，现在有个可见的代表了
  33           → '!'   ← 本来就能看见，不变
  65           → 'A'   ← 不变
  ...

  这样一来，不管原始文本里有什么乱七八糟的字符，都能用"干净的可见字符"来表示。

def get_pairs(word):
      pairs = set()
      prev_char = word[0]
      for char in word[1:]:
          pairs.add((prev_char, char))
          prev_char = char
      return pairs

  - 输入：一个 tuple of symbols（每个 symbol 是变长字符串）。
  - 输出：所有相邻符号对（bigram）的集合。
  - 例：word = ('h', 'e', 'l', 'l', 'o') → {('h','e'), ('e','l'), ('l','l'), ('l','o')}。

## 核心算法：
BPE 算法
从单个字符开始，反复把最常一起出现的两个相邻字符合并成一个。

  为什么这么做？

  - "playing" 如果按字符拆成 p, l, a, y, i, n, g，模型很难学到 "play" 是一个词根，"ing" 是一个后缀。
  - BPE 会把它合并成 play + ing，这样模型就能理解词的结构了。

  怎么知道哪些该合并？

  bpe_simple_vocab_16e6.txt.gz 这个文件里记录了 BPE
  合并规则及其优先级。它是从海量英文文本中统计出来的——哪两个字符最常一起出现，就排前面。

  文件内容大概长这样：
  #version 0.2
  t h        ← 第 0 条规则：t 和 h 最常一起出现，优先合并 → "th"
  a n        ← 第 1 条规则：a 和 n → "an"
  ...
  th e       ← th 和 e → "the"
  ...

  数字越小 = 越常见 = 越优先合并。

  具体例子："Hello" 怎么被 BPE 处理

  我们跟踪 bpe("Hello") 的过程（假设 "Hello" 已经被转成 "Hello" 进入 bpe 函数）：

  输入 token: "Hello"

  第一步：变成元组，最后一个字符加 </w>（标记这是词尾）
  word = ('H', 'e', 'l', 'l', 'o</w>')

  第二步：找出所有相邻对 (pairs)
  {('H','e'), ('e','l'), ('l','l'), ('l','o</w>')}

  第三步：在这些 pair 里找优先级最高的（bpe_ranks 里数字最小）
  假设 bpe_ranks 里：
    ('H','e') → 不存在（H 和 e 不常一起出现）
    ('e','l') → 不存在
    ('l','l') → 排第 XXX 位  （"ll" 很常见，如 "hello", "well"）
    ('l','o</w>') → 不存在

  → 本轮选 ('l','l')，合并成 "ll"

  合并后：word = ('H', 'e', 'll', 'o</w>')

  第三步：重新算 pairs
  {('H','e'), ('e','ll'), ('ll','o</w>')}

  这些都不在 bpe_ranks 里了 → 停止合并

  最终输出：用空格连接
  "H e ll o</w>"

  注意：单词末尾的 </w> 标记很重要！它告诉模型 "这是词的结尾"。
  所以 "Hello" 和 "HelloWorld" 里的 "Hello" 部分会被不同处理

  编码完：token 字符串 → 数字 ID

  self.encoder["H"]    → 某个数字，比如 42
  self.encoder["e"]    → 某个数字，比如 7
  self.encoder["ll"]   → 某个数字，比如 88
  self.encoder["o</w>"] → 某个数字，比如 15

  "Hello" 最终编码结果： [42, 7, 88, 15]


  ## 总结其流程：

  原始文本: "Hello, it's 2024!"

  第一层：清洗（encode 的前半段）

  basic_clean()
    → ftfy 修复乱码（没坏就不变）
    → html.unescape × 2（没有 HTML 实体就不变）
    → strip()

  whitespace_clean()
    → 连续空白压成单个空格
    → strip()

  .lower()

  结果: "hello, it's 2024!"

  第二层：正则切分（re.findall(pat, ...)）

  正则从左往右扫描，谁先匹配上就切谁：

  "hello, it's 2024!"
    │      │  │ ││││
    │      │  │ │││└→ !  标点 [^\s\p{L}\p{N}]+
    │      │  │ ││└→ 4   单个数字 [\p{N}]
    │      │  │ │└→ 2   单个数字 [\p{N}]
    │      │  │ └→ 0    单个数字 [\p{N}]
    │      │  └→ 2    单个数字 [\p{N}]
    │      └→ 's    缩写后缀，单独切
    └→ hello   连续字母 [\p{L}]+

  空格 → 丢弃
  逗号 → 标点 [^\s\p{L}\p{N}]+ → ","

  切分结果: ["hello", ",", "it", "'s", "2", "0", "2", "4", "!"]

  第三层：字节编码

  对每个 token，先转 UTF-8 字节，再用 byte_encoder 映射到安全字符：

  "hello" → UTF-8: [104,101,108,108,111]
          → byte_encoder: 104→h, 101→e, 108→l, 108→l, 111→o
          → 结果: "hello" （全在可见范围，不变）

  ","     → UTF-8: [44]
          → byte_encoder: 44→,
          → 结果: ","

  "2"     → UTF-8: [50]
          → byte_encoder: 50→2
          → 结果: "2"

  "'s"    → UTF-8: [39, 115]
          → byte_encoder: 39→', 115→s
          → 结果: "'s"

  字节编码后: ["hello", ",", "it", "'s", "2", "0", "2", "4", "!"]

  英文全在 ASCII 可见范围，所以看起来没变。如果是中文比如 "你"，UTF-8 是 [228,189,160]，就会变成 "ä½ "这样三个奇怪字符。

  第四层：BPE 子词合并（每个 token 分别进 bpe()）

  以 "hello" 为例走一遍：

  bpe("hello")

  加词尾标记: ('h', 'e', 'l', 'l', 'o</w>')

  找相邻对: {('h','e'), ('e','l'), ('l','l'), ('l','o</w>')}

  查 bpe_ranks（从 .gz 文件加载的合并优先级表）:
     ('l','l') → 排第 XXX 位 ← 唯一存在的，优先级最高
     其余都没有记录

  合并 ('l','l'):
     → ('h', 'e', 'll', 'o</w>')

  找相邻对: {('h','e'), ('e','ll'), ('ll','o</w>')}
     全部不在 bpe_ranks 里 → 停止

  输出: "h e ll o</w>"

  其他 token 同理：

  ┌─────────┬──────────────────────┬──────────────────────┐
  │ 输入    │ bpe() 过程           │ 输出                 │
  ├─────────┼──────────────────────┼──────────────────────┤
  │ "hello" │ ('l','l')合并一次    │ "h e ll o</w>"       │
  │ ","     │ 单字符，直接返回     │ ",</w>"              │
  │ "it"    │ 没有可合并的pair     │ "i t</w>"            │
  │ "'s"    │ 单字符（'s是一个整体）│ "'s</w>"             │
  │ "2"     │ 单字符，直接返回     │ "2</w>"              │
  │ "!"     │ 单字符，直接返回     │ "!</w>"              │
  └─────────┴──────────────────────┴──────────────────────┘

  第五层：映射成数字 ID（encoder）

  把所有 </w> 不影响理解，只看核心逻辑：每个子词字符串 → 一个数字 ID。

  "h e ll o</w> ,</w> i t</w> 's</w> 2</w> 0</w> 2</w> 4</w> !</w>"

  ↓ encoder 查表

  [68, 6, 88, 15, 5, 33, 4, 12, 2, 16, 2, 18, 63]

  ▎ 这些数字就是模型最终接收的输入。

  ---
  解码：逆过程

  [68, 6, 88, 15, 5, 33, 4, 12, 2, 16, 2, 18, 63]

  ↓ decoder (数字→字符串)
  "hello,it's2024!"

  ↓ byte_decoder (Unicode→字节) + decode('utf-8')
  "hello,it's2024!"

  ↓ replace('</w>', ' ')
  （解码时 </w> 变成空格）
  "hello, it's 2024!"
