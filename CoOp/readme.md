## 核心问题
像 CLIP 这样的大规模视觉-语言预训练模型在下游任务中依赖 Prompt Engineering（提示工程来做零样本迁移。例如，对于花卉分类，需要手工设计 "a photo of a [CLASS], a type of flower." 这样的prompt。然而，手工调 prompt 极其耗时且依赖领域经验——措辞的微小变化可能导致性能巨大差异（如 Caltech101 上加一个 "a" 就能提升 5%+ 准确率）。

## 核心方法
CoOp 的核心思想是：将 prompt 中的上下文词（context words）建模为可学习的连续向量（learnable vectors），通过数据端到端优化，同时冻结整个预训练模型参数。

## 问题1：什么是Knowledge probing
以下是deepseek v4 pro给出的答复：
Knowledge Probing 是 NLP 领域的一个概念，最早由 Petroni et al. (2019) 在 "Language Models as Knowledge Bases?" 中正式定义。

  核心思想

  把预训练语言模型当作一个知识库，通过设计"完形填空"式的 prompt 来探测模型内部存储的事实性知识，而不是让模型去做传统的分类任务。

  举例说明

  假设你想知道 BERT/GPT 是否学会了"巴黎是法国的首都"这一知识：

  - 传统做法：训练一个分类器，输入"巴黎"，输出"首都"类别
  - Knowledge Probing：构造一个完形填空 prompt：

   "Paris is the capital of _____."
  （让模型的 [MASK] 位置预测出 "France"）

  如果模型能正确填出 "France"，就说明模型在预训练过程中已经学到了这条知识。

## 核心方法阅读：
为了方便理解，这里利用deepseek v4 pro生成了一个例子：
以 Flowers102 为例走一遍完整流程

  假设我们要分类 3 种花：daisy（雏菊）、rose（玫瑰）、tulip（郁金香），采用 4-shot 训练（每类 4 张标注图片）。

  Step 1：初始化 Context Vectors

  随机初始化 M=4 个 512 维向量：

  [V]₁ = [0.01, -0.02, 0.03, ..., 0.01]   ← 全是随机数
  [V]₂ = [-0.01, 0.04, -0.02, ..., 0.03]
  [V]₃ = [0.02, 0.01, -0.01, ..., -0.02]
  [V]₄ = [-0.03, 0.02, 0.04, ..., 0.01]

  Step 2：为每个类别构造 prompt

  把类别名（daisy/rose/tulip）的词嵌入拼接到 context vectors 后面：

  类别 daisy 的 prompt：  [V]₁  [V]₂  [V]₃  [V]₄  [daisy的embedding]
  类别 rose 的 prompt：   [V]₁  [V]₂  [V]₃  [V]₄  [rose的embedding]
  类别 tulip 的 prompt：  [V]₁  [V]₂  [V]₃  [V]₄  [tulip的embedding]

  注意：[V]₁~[V]₄ 在所有类别间共享（这是 Unified Context 的做法）。每个 prompt 送入文本编码器后，取 [EOS] 位置的输出，得到该类别的分类权重向量：

  文本编码器([V]₁ [V]₂ [V]₃ [V]₄ daisy) → w_daisy（512-D）
  文本编码器([V]₁ [V]₂ [V]₃ [V]₄ rose)  → w_rose（512-D）
  文本编码器([V]₁ [V]₂ [V]₃ [V]₄ tulip) → w_tulip（512-D）

  Step 3：前向传播做分类

  假设现在有一张雏菊图片 x，经过冻结的图像编码器得到 f：

  图像编码器(x) → f（512-D）

  然后计算 f 与 3 个类别权重向量的余弦相似度，用 softmax 转成概率：

  cos(f, w_daisy) = 0.72  →  exp(0.72/τ) / Z = 0.65  ← 应该最高
  cos(f, w_rose)  = 0.31  →  exp(0.31/τ) / Z = 0.20
  cos(f, w_tulip) = 0.28  →  exp(0.28/τ) / Z = 0.15
                      Z = exp(0.72/τ) + exp(0.31/τ) + exp(0.28/τ)

  模型预测为 daisy ✓

  Step 4：反向传播，更新 Context Vectors

  算交叉熵损失（如果预测对了，损失小；预测错了，损失大），然后反向传播梯度，只更新 [V]₁~[V]₄：

  损失 → 梯度流过 w_daisy, w_rose, w_tulip
       → 梯度流过文本编码器（冻结，参数不变）
       → 梯度到达 [V]₁, [V]₂, [V]₃, [V]₄
       → 更新这 4 个向量

  关键：CLIP 的图像编码器和文本编码器全程冻结，只有那 M 个 context vectors 在更新。

  Step 5：经过 12 张图片的训练后...

  [V]₁~[V]₄ 从随机向量逐渐变成了蕴含任务相关上下文知识的向量。它们可能在连续空间中编码了类似 "a flower photo of a" 的语义，但又超越离散词汇的局限，学到了对该任务最优的"表达"。

  最终测试时，用学好的 [V]₁~[V]₄ + 类别名，在新图片上做推理即可。

*以上所提的为Unified Context的做法，对于Class-Specific Context (CSC)来说，每个类别均有自己独立的[V]₁~[V]₄*

```bash
  ┌──────────┬──────────────────────────────────────────────────┬──────────────────────────────────────────────────────────────────────────────────────┐
  │          │                 Unified Context                  │                             Class-Specific Context (CSC)                             │
  ├──────────┼──────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
  │ 做法     │ 所有类别共享一组 [V]                             │ 每个类别有自己独立的一组 [V]                                                         │
  ├──────────┼──────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
  │ 例子     │ daisy, rose, tulip 都用 [V]₁~[V]₄                │ daisy 用 [V]₁ᵈ~[V]₄ᵈ，rose 用 [V]₁ʳ~[V]₄ʳ...                                         │
  ├──────────┼──────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
  │ 参数量   │ M × 512（少）                                    │ K × M × 512（多）                                                                    │
  ├──────────┼──────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
  │ 适用场景 │ 通用分类、场景、动作                             │ 细粒度分类（花、车、飞机）                                                           │
  ├──────────┼──────────────────────────────────────────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
  │ 为什么   │ 共享的上下文学到"这是一张照片"这种通用语义就够了 │ 不同花类可能需要不同的上下文描述，比如玫瑰强调"红色花瓣"，雏菊强调"白色花瓣黄色花蕊" │
  └──────────┴──────────────────────────────────────────────────┴──────────────────────────────────────────────────────────────────────────────────────┘
```

同时，class token的放置位置也可以放置在中间，理论上来说，后面的向量可以做补充描述。这里我的理解是：由于attn_mask的存在，模型只能看到句子前面部分的信息，因此若把class token放置再句子中间，后面的向量（token）可以看到class token，可以对class token做补充。因果注意力机制让后面的 token 能基于前面的 /[CLASS/] 做条件性补充。

## 问题2：什么是linear probe model
Linear Probe（线性探测） 是一种经典的迁移学习评估方法：冻结预训练模型的特征提取器，只在其顶部训练一个线性分类器。

实质上，linear probe就是训练一个线性的分类器：
```bash
  以 CLIP + Linear Probe 为例：

                      ┌─────────────────────┐
        图片 x  ──→  │  冻结的图像编码器      │  ──→  f（512-D 特征）
                      └─────────────────────┘
                                    │
                                    ▼
                      ┌─────────────────────┐
                      │  可训练的线性层       │  ──→  logits（K 维）
                      │  W（K×512 矩阵）     │
                      └─────────────────────┘

  - 冻结：CLIP 的图像编码器参数完全不动
  - 训练：只训练一个线性变换矩阵 W ∈ ℝ^{K×512}，将 512-D 特征映射到 K 个类别的 logits
  - 损失：交叉熵

```
